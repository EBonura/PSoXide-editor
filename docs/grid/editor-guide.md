# Grid world editor guide

How to run the grid editor from this worktree, open a grid project, use every tool, press Play and bring in a level. Plan and decisions are in `plan.md`.

## Run it

From the repository root:

```bash
cargo run --release -p frontend --features editor -- --editor --windowed --editor-project editor/projects/grid-cathedral
```

Swap the last path for any grid project: `grid-cathedral`, `grid-level008`, `grid-cave`, `grid-dungeon`, `grid-sewers`, `grid-west`, or a project you made with File > New Grid Project. Leave `--editor-project` off to open the default project and switch with File > Project. The first build takes a few minutes; `make run-release` does the same through the Makefile.

Play and Build shell out to `make build-editor-playtest`, which runs `make bootstrap` first. Bootstrap refuses to continue when a hydrated emulator file has been edited ("Imported file changed"), so keep `emu/crates/frontend/src/cli.rs` and `gfx.rs` as the pinned emulator revision ships them. `.tools/sdk-*/bin/psoxide-components --root . --check` says whether they match.

## Open or create a project

* File > Project lists every project under `editor/projects`. A grid project opens in the 3D view with the grid tool strip across the top.
* File > New Grid Project... asks for a name and makes `editor/projects/<name>/`: a 6 by 6 sector room with a floor, a ceiling, one lamp and the Graybox Reach player in the middle, and a palette of nine Graybox materials: the base's three blue-grey grid tints and six that read apart (Warm Stone, Dark Trim, Light Frieze, Wood, Metal, Moss; generated colour-plus-noise materials, no image files). Its outline walls are not stored: the room derives them (see Derived walls below). It borrows the player, camera, sky and UI from `editor/projects/graybox-reach` (the project's `assets` folder links to it), so that project has to exist. Press Play and you are walking in it.
* The six reference levels (`grid-cathedral`, `grid-level008`, `grid-dungeon`, `grid-cave`, `grid-sewers`, `grid-west`) are tracked projects. They came from bonnie-32 maps; the importer is gone, so the projects are now the source of truth.

## The screen

* Centre: the 3D view (the emulator's software GPU, so it is the PS1 picture), the Plan (the Top orthographic view) or both side by side (Split). The switch is in the tab row; Ctrl/Cmd+9 cycles it. Each half frames the world when the view opens.
* Left dock: Structure (the Levels, then the Rooms), then the Scene Graph, where three or more sibling lights fold into one `Lights (n)` row that opens on a click (or when one is selected). A grid project has no file tree in any tab.
* Right dock: the Materials palette (search, `+`, import, pencil to edit the paint material), then Properties, whose header names what it edits (Face, 4 faces, Triangle B, a node's name, a region, World). With nothing selected it shows a hint and a World settings button; the World form opens from that button or the World row of the Scene Graph, not under every empty click.
* Bottom: the Assets drawer (models, animations, characters, weapons; materials are in the palette) and the Console, closed to a thin bar until you open it (Place for a model prop or a model import opens it). The bottom bar is three parts: the last message, the keys of the active tool, and chips for the room's sector count, the busiest room's faces against the cap (`faces / 16383`, orange from 85%) and the faces in view. Frame, Camera and Show (visibility) are labelled buttons in the tab row; Debug snapshot is in the Tools menu; Link shows with Height or a picked corner, Move and Global with a selected node.
* `?` (or the Keys button) opens a page with every key and gesture; its search box keeps the sections and rows that match.

### Rooms panel

One row per room: the eye shows or hides it (hidden rooms leave the 3D preview, the Top view and picking), click a name to make it the room new geometry goes into, double-click to rename, the bin deletes it (the last room stays), `+` adds an empty room one storey above the highest. Under the list: Raise (the whole room's height offset in clicks) and Ambient (RGB, 128 shows textures unmodified), then the room's walls: whether they are *derived from heights* or *authored (legacy)*. A legacy room offers **Convert to derived** (the look and the play stay exactly as they were) and **Convert and fill** (also shows the walls the room never had). A derived room offers its wall material (Use palette / Clear), the Open wall height for a floor with no ceiling, and Clean up for overrides whose wall no longer exists. **Paint rules** (flat, slope and steep floors, verb walls, trim, and the two height rules) and **Rough** (seed, three amplitudes, tint) are collapsed sections below. Rooms may overlap in plan; that is how floors stack.

### Material tab

A grid project's Material tab opens on the palette's paint material and what you pick there becomes the paint material (one current material). Its Inspector is about that material: name, size, how many faces of the world use it, and Paint with it (back to the World tab with the Paint tool). The settings form is the tab's own.

### Materials palette

Grouped by name: the part before ` / ` (`Graybox / Brick` is in Graybox) or the name without a trailing `.n` (`DP 13.4` is in DP 13), each group a collapsible header with its count; a big world starts with its groups closed except the one holding the paint material, and a search opens the groups it matches. A Recent row keeps the last eight materials used; the scroll window grows with the dock. Lists the materials the world already uses, the images imported with a level (`level_textures/`) and the Graybox set. HUD, menu, button prompt, kit, sky and character images are left out; tick "Show all project materials" to see them. Click a swatch to make it the current material (the Paint tool and new surfaces use it) and to apply it to the selected faces.

Letters kept free for the level verbs that come next: B Room, K Corridor, I Opening, Y Stamps, J Vault (G goes to a level and Z switches the cutaway, below; N is the Plane tool and Shift+N the Mesh tool, E the Bands tool, U Raise, A Ramp, T Stairs, Shift+T Spiral, X Break, M Rough, Q Cells, Shift+Q Upper floor). L toggles Link and R turns, so no plain letter was left for Mesh. Alt+W is the walkability overlay and Alt+P the performance heatmap (below).

Also: Ctrl/Cmd+C copies the selected faces, Ctrl/Cmd+V shows a ghost (click stamps, Shift keeps stamping, H and V flip, R turns), Esc cancels a drag, a ghost or the selection, Ctrl/Cmd+Z and Ctrl/Cmd+Shift+Z undo and redo, `.` frames the selection, Ctrl/Cmd+S saves.

3D camera: middle or right drag orbits, with Shift it pans, scroll zooms, and with the free camera W A S D fly while the right button is held.

Snapping is one rule in every tool: a click (256) by default, **Alt** for the fine step (64), **Shift+Alt** for free movement where a tool can leave the lattice (planes, Place; heights always stay on the 64 lattice).

Units: a sector is 1024 grid units, a click 256, the fine step 64. A project's scale maps grid units to editor units (File > New Grid Project uses 5/4, so a sector is 1280 editor units; the imported levels keep the scale their import chose. `GridScale::DEFAULT`, still 21/16, moves to 5/4 with the next phase). Walls belong to the sector edge they are on, with a front side (the interior) and an optional back or both.

## Meshes

Static meshes are arches, columns, rubble and imported props: not grid geometry, but assets the world keeps once and rooms place copies of (`docs/grid/meshes.md`). Their one home is the **Meshes** palette in the right dock, below Materials, shown with the Mesh tool (Shift+N) and while a mesh is selected.

* **Palette**: one row per asset (click to choose it for placing). **+ Arch**, **+ Column**, **+ Rubble** make a default asset and choose it; **Import OBJ** reads a `.obj` (quads and triangles with their UVs, `usemtl` names become material slots, one OBJ unit is one sector, the origin moves to the floor under the middle). Below the list, the chosen asset's **recipe**: an arch's profile (round, segmental, pointed, flat), span, rise, spring, thickness, depth, segments and the hook socket at the crown; a column's radius, height, sides, plinth and capital; rubble's size, stones and seed. Every placed copy follows an edit.
* **Place**: with an asset chosen, click a floor. The mesh stands on the floor under the pointer at the 256 lattice (Alt 64, Shift+Alt free), turned to the heading shown in the option row (R turns it a quarter, `[` and `]` 15 degrees when nothing is selected). A ghost box follows the pointer in both views.
* **Select, move, turn**: click a mesh (the Top view picks by footprint, the 3D view by its box). Drag it; it follows the floor. R, `[` and `]` turn it. Delete removes it. The Top view draws every footprint (orange, the selection yellow, hover white-ish) and a ring at each hook socket; the 3D view draws the mesh itself and boxes the selection.
* **Inspector** (a mesh selected): asset, position and turn as numbers, scale (uniform in percent, or x y z), a material per slot with Use palette and Clear (clicking a swatch applies it to every slot), Collides, Fullbright, Enabled, Delete. The Inspector wraps a drag in one undo step.
* **What the cook does with it**: draws it with the room's free planes, collides it (piers and columns block, flat tops and the arch crown are surfaces to stand on), spawns a hook point under an arch's crown. The 3D preview and Play bake the same light, except that the preview casts no shadows.

## Cells of several sizes

A room is a quadtree of cells. Level 2 is the sector every older level is made of; a cell can be split into four (a half sector, then a quarter) and, where the floor is one flat or sloped plane, four sectors can become one cell two or four sectors across. Big cells keep a large flat floor cheap to edit; small ones are where detail goes (steps, a chip in a ledge). A split changes how the room is stored, never what it looks like or stands on.

**Q, the Cells tool.** Press and drag over the plan (or click): each cell under the pointer becomes four. The options row says how far: `One level`, or straight down to `1/2 sector` or `1/4 sector` at every click the brush covers; `[` and `]` set the brush radius in quarter sectors. **Alt** merges instead: the four cells that share a parent become it, but only when the bigger cell would look and stand exactly as the four do (one plane, the same materials, no wall between them); `Merge up to` limits how big the result may be (a sector, two or four across). Shift+M merges the cell under the pointer. To split cells you picked, use the Select tool's **Subdivide cells** button (it goes as far as `Subdivide to` says); **Merge cells** or Shift+M joins them back. One undo step per stroke.

**Cell sizes (Alt+L, the Cells button).** Every cell outlined in a colour that says its size and labelled where there is room: violet 4 sectors across, blue 2, grey 1, amber 1/2, red 1/4. Works in the Top and 3D views. The status bar counts the cells by size.

What the tree guarantees (the editor keeps it, `limits::validate` checks it): neighbouring cells differ by at most one level (a split can split a neighbour too: the **balance**); cells bigger than a sector are one plane with no wall on them (a corner dragged on one splits it first); and where a coarse cell meets two finer ones the corner on its edge sits at the average of the edge's ends when the floor is continuous there (a **hanging corner**, moved for you). The faces insert that corner into the coarse polygon, so the preview and Play have no crack.

Raise (U) and Height (H) work on cells of any size: Raise moves every cell inside the region and splits a bigger cell to fit it; the Height tool splits a cell above a sector only when the corners you grab would bend it. Paint and Select address the cell under the pointer, in the Top view too: a click on a divided sector picks the one cell under the pointer with all its faces.

**Cell size (the option row).** Floor, Ceiling, Wall, Raise, Ramp, Stairs and Break take a cell size: Sector (the default), 1/2 or 1/4. At 1/2 or 1/4 the rectangle, brush, path or wall run counts cells of that size, larger cells under it are split to fit, and the verb runs on exactly those cells, as the MCP's `size` does. The hover ghosts and the region outline snap to that size. Changing the size drops the region in progress. Not yet at a fine size: the lasso, Cut corners, diagonal walls, the Ramp and Stairs ghosts (the drag, its readout and the result work, but the sector-sized picture is not drawn), the Convert command, derived-wall painting, and a split-level or void triangle (a sector holding one cannot be split, and a merge never makes one).

**Play.** Collision and portals are built per whole sector until the leaf format (phase T10): a bigger cell is expanded to its sectors exactly, fine cells that merge back exactly are collided exactly, and any other sector is stood on through the heights at its four corners (the cook warns, one line per sector). What you see is the real fine geometry.

## Storeys

A column of the world can hold several floors, one above another (`docs/grid/multi-storey.md`). Nothing has to be planned: build a tall hall and cut it into storeys afterwards. A **storey** is a floor height that eight or more sectors share, found from the document, never declared.

* **The level cursor.** Alt+Up and Alt+Down move the cursor to the next storey up or down (the first press with no cursor lands on the lowest). **G**, then a click, sets it to the surface under the pointer: the face hit in the 3D view, the topmost floor of the column in the Top view; Esc cancels the pick. The **Level chip** at the top centre of the viewport names the level, its height in clicks and runtime units, and the cutaway. The cursor is a view setting: it is not saved with the project and no tool edits through it unless it says so.
* **The cutaway.** With a cursor on a storey that has another above it, the 3D view and picking hide every face whose lowest point is at or above the next storey's floor, so you see into the storey you work on and a click goes through the floor above. **Z** turns it off and on. A face that straddles the plane is kept whole. With no cursor, or on the top storey, nothing is hidden.
* **The Upper floor tool (Shift+Q; the Slab verb, called Slab before 2026-10-20).** It adds a floor above this one with open space underneath, so a tall hall becomes two storeys; it needs a ceiling or open sky above. It is not Raise: Raise lifts the ground and fills what is under it, the Upper floor leaves a room under itself. Pick sectors as for the other level verbs (the cell size must be Sector). *Add floor above* (the default; Insert in the MCP and the pose): press on the region and drag up; the new floor's walking surface goes that high over the level cursor (over the floor under the region when there is no cursor), one click thick, in the palette material. The ghost shows the open space under the new floor as its own cyan box and the chip says how many clicks of it there are. The span it passes through is split in two; a lower part with under three clicks of headroom is a sliver and its floor rises instead, which is Raise, and the chip says so while you drag. Sectors with nothing open at that height, a sloped surface across it, or too little headroom are skipped, and the status line counts them. *Remove upper floor* (Cut): click the region and the first upper floor above the level comes out, merging the spans around it (a stairwell). *Fill opening* (Fill): click the region and it is closed up to the next storey above the level. **Tab** cycles Add floor above, Remove upper floor, Fill opening. Each gesture is one undo step and Esc puts the document back exactly. The option row also takes a typed height and Apply.
* **The tools follow the cursor.** Floor, Ceiling, Raise, Ramp, Stairs and Break edit the floor the cursor names in a column of several: for the length of the edit the span open at the cursor stands in as the column's floor, and the column is put back in order afterwards. A column of one span is edited as always. With no cursor, a column of several floors refuses and the status line says how to set one (Alt+Up or Alt+Down, or G and a click). An edit that would leave a column out of order (a floor through the slab above it) is refused and nothing changes; a drag stops at the last amount that kept the columns in order and says why. A span left with under three clicks of headroom is filled solid and the status line counts them. The Wall tool fills the gap of the span open at the cursor in the Top view (and under the pointer in 3D); the Place tool in the Top view lands on the floor at the cursor; the Floor tool makes its floors at the level.
* **The cursor follows the edit.** Raising a floor, laying stairs or drawing a floor moves the cursor with it, and a press on a surface in the 3D view (with Floor, Ceiling, Raise, Ramp, Stairs or Break) moves it to the floor of that surface first, so a click never edits another storey than the one under the pointer. A face, edge or corner you pick in 3D carries its span (the Select, Height, Paint and Diagonal tools act on that floor, not the one under it); in the Top view a pick is the floor open at the cursor. Delete on the face of a slab takes the slab out.
* **The Top view is the slice at the cursor.** Where a column holds several floors the view draws the span open at the cursor at full strength with its height in clicks, the storey below as a dim ghost, and what is only overhead as an outline with a cross, so a stairwell reads as a gap. Derived wall lines are still drawn for every storey.
* **The Spiral tool (Shift+T).** Click the corners of the ring with the Path source (a straight run between two corners is joined sector by sector; chamfers are clicked cell by cell), press Enter to close it (the last corner joins the first), then press on the ring and drag up for the climb of one storey. A straight run of the ring is treads, a turn is a landing, and the walk goes round as often as the **Storeys** option needs; the ghost numbers the climb at each visit. Each tread is a slab laid with the storey primitive, so a sector the stairs pass twice holds two treads a storey apart, and a tread more than three clicks up leaves a walkable undercroft below it. The climb starts from the floor under the ring's first sector (at the cursor where it has several). The riser is the Stairs option. Esc puts the document back exactly; the gesture is one undo step. The same code is `grid_spiral_stairs` in the MCP.

## Walkability overlay

Alt+W (or the Walk button in the strip) shows what the character can stand on and walk to, in the Top and the 3D view, computed from the document with the character motor's own numbers (step-up 40 runtime units, body height 48, the steepest floor it stands on) so it agrees with Play. Orange sectors are too steep to stand on; blue ones have less headroom than the body (checked at the four corners and the middle); a red edge is a step taller than the body climbs between two walkable floors; a fold between the two triangles of a cracked floor that is a step too tall is flagged on the diagonal; a yellow dashed edge is a walkable floor ending in nothing (the body falls there; a solid wall or a derived closure wall on the edge closes it); grey sectors are ghost floors (walkable off). From the player's spawn the overlay floods over every edge the body can cross (it steps up at most the limit and falls any distance, a solid wall stops it) and **hatches** walkable floors no flood reaches, which finds rooms that were built and never connected. With no spawn standing on a floor there is no hatching and the legend says so. Edges are judged inside one room (rooms join for reachability only), a solid wall record blocks an edge whatever its height, and the body is a point (the motor's five-point footprint is not modelled). The legend counts every class and prints the limits and the time of the last run; the analysis is computed once per document change.

## Performance heatmap

Alt+P (or the Perf button) tints every spot a character can stand on from green through amber to red by a **model** of what the world renderer would spend there, against the 30 fps frame (1,128,960 cycles) minus a reserve for the player and the sky (470,000 plus 58,000, measured on the Cathedral; the Reserve field next to the button edits it, because the character cost changes). It cooks the level, then for each standable sector, with the camera at the world camera's height over its middle and eight yaws, runs the renderer's own selection on the host (the cell cull against the near, left and right planes, the front-facing test of every quad, the far-block stand-ins) without the projection, and prices it: visible quads times 800 cycles plus quads with a corner nearer than 170 depth units (the near-plane path) times 10,000. The worst yaw wins. Green is under 60 percent of the world budget, amber to 90, red above. The legend prints the worst spot, the percentiles, the constants and the cook and sampling times; the status bar adds the cooked quad count and "worst spot N% (model)". It runs on a worker thread half a second after you stop editing (a coarse pass first if a gesture is in flight) and the previous tint stays, dimmed, until the new one arrives.

It is a model, not a measurement: the camera is the spot lifted by the camera height (the trailing arm, which a wall shortens, the pitch and the portal view into neighbouring rooms are not modelled), and the two constants are averages. The design's honesty rule applies: the ratio to the renderer's own counters on the Cathedral route is in the level-tools design doc, section 20, and `playtest` with telemetry is the measurement.

## Level verbs

A verb shapes a **region** of sectors. The interaction is always the same: pick the region, press the verb's key, drag an amount, release. Everything a verb writes is an ordinary field (corner heights, wall and floor materials), so it stays hand-editable, and the walls on the new edges are derived, so they appear as you drag.

* **Region**: a **Marquee** (drag a rectangle, or click one sector), a **Brush** (paint sectors with a disc; `[` and `]` change the radius), a **Path** (click waypoints, Enter finishes; `[` and `]` change the width) or a **Lasso** (click the corners of a shape, Enter closes it; see below). Shift adds to the region. It stays after a verb, so verbs chain, until Esc. With the Select tool's sectors picked, switching to a verb takes them as the region.
* **Raise (U)**: press on the region and drag up or down. One click of travel is 256 units (Alt for 64; heights always stay on that lattice). **Offset** moves every corner by the amount and keeps the shape; **Level** sets every corner to the height under the pointer at press plus the amount; Tab switches, Auto picks Level on a flat region and Offset otherwise. Corners on the region's border move with it and the sectors outside keep theirs, so a cliff appears and its walls derive. **Follow ceiling** moves each ceiling by the same delta as the floor under it; off, a floor is held one click under its ceiling and the status line says so. Sectors with no floor are skipped and counted. Esc during a drag puts the document back exactly; the **Amount** field and **Apply** raise by a typed number in one undo step. The risers appear as derived walls, so the room must be derived (see Derived walls: a room with hand-placed walls offers to convert). **Cut corners** (Raise's option row) cracks the outer triangle of the region's convex corners down by the last raise (a click when there has been none), so a plateau gets 45 degree corners with diagonal risers; one undo step.
* **Ramp (A)**: hover the region and the side nearest the pointer lights up: that side (A) keeps its height (the mean of its floor corners). Press there and drag up or down: the opposite side (B) rises or falls and every corner between gets `A + rise * t`, rounded to 64 units, where `t` is its distance from A over the region's depth. A region that is not a rectangle slopes by position, so an L shape is one plane. R turns the kept side a quarter turn and holds it (the option row has the four sides and "Nearest side"). While you drag, every sector is tinted green when the character can stand on it and orange when it is too steep, and the readout says "walkable" or "too steep to stand on" with the rise per sector in runtime units, the angle and the steepest rise the region allows. **Tab** (the Walkable box) holds the amount to that steepest rise. The limit is read from the cook's own triangle normal and the shared walk limits, so a ramp the tool calls walkable is one the motor climbs.
* **Stairs (T)**: drag a rectangle where the stairs go, then press on it and drag up (down for a flight going down) for the total height, as with Ramp. The side nearest the pointer is the **bottom** and lights up with an arrow to the top (R turns it a quarter and holds it); the treads run from the bottom across the rectangle's depth, one sector each, and the rectangle's breadth is the flight's width. The options bar always names the next step ("Drag a rectangle where the stairs go", then "Press on the region and drag up to set the height") and, while you drag, shows the number of steps, the riser in clicks and runtime units and whether it can be walked. A rectangle one sector deep has no run to climb and says so. The **Path** option (the Region buttons in the option row) is the older way for a winding flight: click the waypoints, press Enter, then press on the path and drag up for the total rise; `[` and `]` widen it. Each sector of the flight is a **tread**, a sector where a path turns is a **landing** (flat, at the height of the tread before it), and the sector before the flight is the bottom step: the first tread stands one riser above the floor where the flight starts. The **riser option** is 1 click (the default, half the climb limit), Max (the tallest riser the character steps up, 40 runtime units) or a typed value, never above that limit. The number of steps is `round(rise / riser)`, at least one and at most the treads the flight holds; the riser is then `rise / steps` snapped to 64 and the rest of the flight is a flat landing at the top. If even the shortest riser the flight allows is over the limit the flight is **refused**: nothing is written, the ghost turns orange and the options bar says why ("Too steep for stairs: each step would rise N ru and the character climbs M ru") with a **Make it a ramp (Tab)** button. Tab, or the button, lays the same flight as a ramp (every tread slopes instead of stepping) at the rise you asked for, in one undo step; during a drag Tab switches live between steps and ramp. Floors are made where the flight crosses holes inside the room; the room never grows. The ghost numbers the treads while you drag. Whole-sector treads only; finer treads wait for the finer leaves.
* **Auto split**: a floor or ceiling made by a verb or the Floor and Ceiling tools chooses its own diagonal when its heights change: the diagonal whose two end corners are closest in height wins, so the fold runs level and the odd corner pops out of it. A tie keeps the current split. Surfaces from before this (every reference level) keep their diagonals, the Diagonal tool turns a surface's automatic choice off, and flat or planar cells never flip.
* **Paint rules** (Rooms panel, Paint rules): optional materials for flat, slope and steep floors, for the walls of shaped sectors and for a foot trim, and two height rules, **Floor by height** and **Wall by height**: up to three thresholds (grid units from the room's base, in steps of 64) and a material per band, low to high (scree below, rock above). They run only inside verbs, only on a floor whose slope class the verb changed, and never on a face you painted by hand (the Paint tool and the palette mark it). The palette's current material wins for the walls of shaped sectors.

## Natural terrain

The tools below make levels that do not read as a grid: half-cell cuts, cracked tiles, ragged lips, rock. Everything they write is an ordinary field (corner heights, a second set of heights for one triangle, a void bit, a rough level), so it stays hand-editable.

* **Void a triangle (Diagonal, Shift+click)**: the triangle under the pointer stops being drawn and the sector closes itself along the diagonal with a derived wall, so a square room corner becomes a 45 degree one. Shift+click it again to restore it. One undo step. In the Top view a void triangle is darkened and hatched; in the 3D view a void triangle has no face to point at, so restore it from the Top view.
* **Crack a triangle (Height, Alt+drag on a floor or ceiling face)**: press on a face (not on a vertex or an edge handle) with Alt held and drag up or down. The surface becomes split-level (its second triangle gets its own heights) and only the three corners of the triangle under the pointer move, so a derived diagonal wall (a riser or a drop) appears between the two halves while you drag. A click is 256 units; Shift is the fine step (64) inside this gesture, because Alt already means the grab. It works in the Top view (the triangle comes from where the pointer is against the cell's diagonal) and in the 3D view. Esc puts everything back, the split included; dragging back to zero does too. One undo step.
* **Lasso (a region source)**: choose Lasso in a verb's option row, click the corners of a shape, press Enter. The region is the set of sectors whose centres lie inside the polygon (a lattice corner is an integer, sector `i,j` has its centre at `i+0.5,j+0.5`), the same rule the MCP's `grid_polygon` uses. Shift snaps the next segment to the nearest of eight directions and to whole sectors along it, so 45 degree outlines are exact. Esc drops the shape; Shift on the first corner adds to the current region. The overlay draws the polygon and the sectors it would take. Then use any verb on it (Raise, Break, Rough...).
* **Break (X)**: pick a region, press X, press on the region and drag up: the vertical travel is the **intensity** (0 to 100, two pixels a percent). Walls crumble (the lip of a plateau drops, so the derived riser's top follows), plateau edges take bites (a cell on the low side drops by a triangle, with a diagonal riser), open wall tops get a ragged edge, floor tiles tilt and crack along a diagonal, and, only when **Gaps** is on (it is off by default), a cell may become a see-through gap at intensity 70 and up; **Tab** cycles the target set (walls and floor, walls, floor, ceiling, all), **Shift+X** draws the next seed (the seed is in the option row, where it can be typed; the same seed always gives the same result, and raising the intensity only adds changes), **Enter** or the release commits as one undo step, **Esc** puts the document back exactly. The option row has the targets, **Keep walkable** (every change is checked against the walkability analysis around the cells it touches: one that would cut a route off from the player spawns, add a step taller than the body climbs, a floor too steep to stand on or too little headroom is retried smaller, then refused and counted), Fine or Click steps, the amplitude (fine steps at intensity 100), **Mix materials** (a cracked triangle takes the material of the floor it now borders), **Gaps**, the seed, and a typed intensity with Apply. The status line reads like "Break seed 7, 60 percent: +37 faces, 12 cracks, 4 bites, 4 refused (would break the route)", with the face count taken before and after; the Inspector's Region section adds the walkability change and the first reasons. **Alt+W** keeps working while you drag, so the overlay shows what the break did to the route. Break is the editor's face of `grid_break`.
* **Sculpt (S)**: a brush for terraforming, in the Top and the 3D view (a ring follows the pointer on the surface). Press and drag; every pointer move replays the stroke from the document as it was when you pressed, so it is live, one undo step per stroke, and **Esc** puts the document back exactly. It edits the shared corner heights of the cells under the brush, so neighbouring cells stay welded, a cliff keeps its height and the derived walls and risers follow; heights stay on the 64 unit lattice. Modes: **Raise/Lower** (Shift digs), **Smooth** (toward the mean of the neighbours), **Flatten** (to the height the stroke started at), **Ramp** (drag from A to B for a straight slope between the two ground heights, plus the **rise** in clicks; Shift lowers it) and **Dunes** (drag across the ground: the crests run perpendicular to the drag, with the **wavelength** in sectors and the crest **height** in clicks). The option row also has the radius (`[` and `]` change it a click at a time), strength, falloff (smooth, linear, sharp), Floor or Ceiling, and **Detail**: Sector, 1/2 or 1/4 sets how fine the cells under the brush become (the cells are subdivided first, which never changes the surface), and **Auto** divides only the cells whose new ground a plane cannot follow within one fine step. A column of several storeys is never divided; it is sculpted as a whole sector and the status line counts them (cells next to one stay at half sectors, so balancing never splits it). A floor stays a body (1024 grid units) under its own ceiling and a ceiling over its floor. The option row shows the room's **face count** with this stroke's change, orange from 85 percent of the per room cap and red at it, and while the tool is active the **walkability overlay** is on (orange floors too steep to stand on, red edges steps the body cannot climb). Sculpt is the editor's face of `grid_sculpt`.

## Tiling

Every face (floor, ceiling, authored wall, derived wall, plane) is textured by one model, edited in the Tiling section of the Inspector:

* **World**: the texture follows the world, so neighbouring faces line up and a bigger face tiles more. The number is texels per sector along each axis. The World button takes the world's own density (below); 32 (half a 64 texel tile per sector) is how every face of a world made before the setting behaves, bit for bit.
* **Fit**: a fixed number of tiles across the whole face, whatever its size. 2 x 2 is "2x2 on this face"; the one-click presets are 1x1, 2x2 and 4x4, the fields take any value in 1/16 tile steps up to 16 per axis. The frame a fit is measured against is the logical face: the sector square of a floor or ceiling, the wall record of an authored wall, the whole run of a derived wall (so 8x1 repeats eight times along the whole run, not once per sector) and the plane rectangle.
* **Default**: the material's own tiling (Material tab, Grid tiling: Legacy, World or Fit; a swatch in the palette carries a badge when it has one), else the world's own mapping (its texels per sector, below). A face that names its own mode ignores the material.
* **Fit across the selection**: with two or more floors and ceilings selected, the row under the Tiling controls puts N x M tiles across the whole selected rectangle instead of across each face (2 x 2 over a 4 x 2 patch is one 2 x 2 tiling, not eight). Floors and ceilings each get their own patch (the bounding rectangle of that kind of face in the selection); walls are skipped, because a wall's frame is already its whole run. Each face stays on Fit and is told how far the patch reaches past it (`grow`, stored with the face, relative to it), so the texel map is one function over the patch: neighbours share edges exactly, Turn, Flip, Offset and Scale then act on the whole patch, and moving the selection keeps the look. The status line says how many tiles each face shows and warns when the cook has to cut faces. Changing a face's own Tiling mode or pressing Reset puts that face back on its own frame. One undo step.
* **Turn** (quarter turns, clockwise) and **Flip** (H, V) act on the face as you see it, and **Offset**, **Angle** and **Scale** stay as fine adjustments after the mode.
* **Quick scale**: one button each for 0.25x, 0.5x, 1x, 2x and 4x on every selected face (one undo step); with faces selected, **=** and **-** step each face to the next scale up or down. 1x is the tiling as it stands (in a new world, one 64x64 texture per sector), 2x draws the texture twice as big, 0.5x half as big; it sets the Scale fields, so a mirrored face stays mirrored. The Paint tool carries the same scale on its brush (**[** and **]**).

**Texels per sector** is a setting of the World (select the World in the Structure panel; the Texture density section of the Inspector): how many texels the default mapping spends on one sector edge. The grid renderer tiles 64x64 textures, so a new world spends 64 (one whole texture per sector); a world made before the setting reads as 32 and keeps it, so no face, cooked byte or pinned hash changes. Switching a world between 32, 64 and 128 is one undo step; by default it keeps faces with other texture sizes as they look (a material whose texture is not 64x64 gets the old density as its own tiling default, so a 32x32 texture stays one per sector while the 64x64 ones follow the new density). Generated meshes (arches, columns, rubble) follow the world's density so they continue the walls beside them.

The Inspector always prints what the setting comes to ("effective: 2 x 2 on this face", "1 x 1 tiles on this face") and warns when the cook has to cut the face. A primitive repeats its texture up to four times per axis through the console's texture window, so 2x2 and 4x4 are one primitive; beyond that (8x8, or four tiles starting part way into a tile) the face is cut into the fewest primitives, and the Inspector says how many ("cuts this face into 4 primitives (+3)"). The cook counts the cuts and the repeating primitives in its report. Faces on the plain legacy mapping are cut like any other, so a tall sloped wall made before the model draws in Play exactly what the preview shows.

## Shading

The Rooms panel has a **Shading** setting for the world: how much darker a face is by the way it looks, so a step, a platform or a corner reads under one lamp (the way Tomb Raider shaded its rooms). Off leaves every face as lit; Subtle (floors 100%, ceilings 78%, walls facing east or west 83%, north or south 66%) is what a new world gets; Strong is for dim levels; the four numbers are editable per direction. A face between the directions takes a blend by its normal. The 3D preview and Play use the same function, and levels made before the setting stay off until you turn it on.

## Derived walls

A new room's walls are not drawn by hand. Raise a platform, lower a pit or leave a room's edge and the editor makes the wall for you, from the height difference between the two sectors on either side of the edge:

* a step between two floors gets a **riser**, seen from the lower side;
* a step between two ceilings gets a **drop**, seen from the higher side;
* the edge of the room (the neighbour holds no floor or ceiling) gets a **closure** wall from floor to ceiling, which also blocks movement, so a derived room cannot be walked out of. A floor with no ceiling gets one only when the room's Open wall height is above 0.

Where two floors cross inside one edge the wall is cut at the crossing into two triangles. Equal heights make nothing, so a continuous floor never grows a wall. The Top view draws derived walls in light blue (a ghost closure in yellow, a hidden face dimmed); the diagonal risers, drops and closures of cracked and void triangles are drawn on the diagonal.

A derived face takes its material from, in order: the face itself, the sector the step belongs to (its wall material), the sector looking at it, the room's wall material, then the owner's own floor or ceiling material. Click a derived wall with Select (or hover it with Paint) like any face: Paint writes the face's override, the Inspector edits its material, texture placement, Solid and Hidden flags, and Back to automatic forgets all of them. Delete hides a derived face. Overrides are stored with the room by wall segment, so they survive edits to the neighbours. The Wall tool still places authored walls for what heights cannot say (a freestanding wall, a parapet); it treats derived faces as walls already standing, so an edge a derived wall closes answers "covered". A warning is shown for an authored wall that lies on top of a derived face.

**Raise makes walls only in a derived room.** In a room with hand-placed walls (the Rooms panel says "authored (legacy)") a raised platform gets no risers, because nothing derives them. So when Raise, Ramp, Stairs, Break or Floor is the active tool and the room it works in has hand-placed walls, the options bar shows a one-time prompt: "This room uses hand-placed walls, so new heights won't get walls. Convert to derived walls?" with **Convert** (the same Convert to derived as the Rooms panel, one undo step, the room keeps its look) and **Not now** (the prompt stays away from that room for the rest of the session). The New Project template's room has been derived since 2026-10-20; a project made earlier (such as a copy of dp-world) gets the prompt.

Rooms made before this keep their wall records and their look until you press **Convert to derived** in the Rooms panel (or **Convert** in the prompt above). Convert removes an authored wall only when it is exactly a derived face, moving its material, texture and solidity into the override; every other wall stays, and the derived faces the room never had are hidden so nothing new appears. One undo step reverts it.

## Wall bands

A band is a horizontal strip of a wall with its own material and texture rule: a trim at the base, the main wall, a frieze at the top. Select a wall (derived or authored) and the Inspector shows its **wall run** (the whole chain of collinear faces a fit mapping treats as one face) with a Bands section; or use the Bands tool (E) in the 3D view.

* **Cut**: hover a wall, a horizontal rule previews at the pointer height snapped to a click (Alt for 64 units). Near the bottom of the wall the line follows the bottom edge (so a trim follows a sloped floor), near the top the top edge (a frieze hangs from a ceiling or ledge), between them it is an absolute datum that stays level across terrain. Click cuts the run there. At most six lines (seven bands) a set.
* **Move and remove**: press a line and drag it up or down between its neighbours (Esc puts it back); click a line and press Delete, or the bin in the Inspector, to remove it; the two bands around it join.
* **Scope**: *This run* edits just the selected run, copying the set first when other walls share it; *Whole room* edits the set in place, wherever the room uses it. A room can also have a default set (the Inspector's Whole room scope on a wall that has none makes one), and a run can opt out with Remove bands.
* **Material and tiling per band**: open a band in the Inspector and use Use palette, or Shift+click a band in the 3D view and click a material in the palette; the Paint tool (P) paints the band under the pointer on a banded wall. A band's tiling is the same model as everywhere (World or Fit); *V* says where the texture sits in a world mapping (follow the world height, sit on the band's lower line, hang from its upper line), and a Fit band fits exactly between its two lines and repeats across the run.
* **Slopes and stacks**: lines follow slopes by their anchors; an absolute line across a sloped wall cuts it into a triangle and a trapezoid at the crossing. For authored walls stacked on one edge the anchors measure against the whole stack, so one trim runs at the base of the stack and not of every segment.
* **Neighbours**: where a banded wall meets a wall cut at other heights the vertical edge gets the neighbour's cut heights as extra corners (and the face is fanned into triangles), so no one pixel crack opens between them. Rooms without bands are untouched.
* **Courses**: a wall of a room made before derived walls is still cut at every sector of height; derived rooms and rooms with bands draw a wall as one face and let the texture splitter and the band lines cut it.

The cook writes bands as ordinary quads and triangles (about 40 bytes and one packet each), so a wall cut into three bands costs two packets more per segment.

## Free planes

A free plane is a flat textured quad that is not tied to the sector grid: a bridge deck, a ramp, a slanted wall, a banner, a grate. Each room owns a list of them (at most 64). Press N (or pick Plane in the strip).

* **Place**: click a floor, a wall or empty ground. The plane lies on that surface facing out of it, lifted a hair so it never fights the surface, snapped to the 256 lattice, one sector square. Drag instead of clicking to size it: the press point is one corner, the size snaps to the lattice. The strip's "New plane" menu sets the collision class and sidedness a new plane starts with.
* **Select**: click a plane with the Plane or the Select tool (Shift extends, Ctrl/Cmd toggles). In the Top view a plane picks by its outline or inside it; click the same spot again to take what lies under it (the next plane, then the floor, then the ceiling), and a click elsewhere starts over. The Inspector then shows one context, the plane.
* **Handles** of the selected plane: the four corners and four edges stretch it (the opposite edges stay put); the green ring knob turns it about the vertical axis in 15 degree steps; the blue arrow tip tilts the front up and down; dragging the body slides it in its own plane, Shift moves it up and down. Alt snaps finer (64 units, 5 degrees), Shift+Alt is free. Moves snap the plane's edge or centre onto the lattice, whichever is nearest, so edges land on grid lines. Roll and exact numbers are in the Inspector.
* **Keys**: R quarter turn, PgUp/PgDn or ]/[ nudge up and down a click (Shift: 64), Delete removes, Ctrl/Cmd+C and V copy and paste with a ghost (R turns, H flips, click stamps), Esc during a drag puts the plane back, Ctrl/Cmd+Z undoes.
* **Material**: the palette applies to the selected planes, the Paint tool paints a plane under the pointer (Ctrl/Cmd+click samples its material). Blend mode and alpha cutout (palette index 0 transparent) come from the material, so a banner or grate is a plane with the right material and "Both sides" ticked.
* **Angles**: yaw, pitch, roll in whole degrees. At zero the plane stands upright facing south (+Z), like the north wall of a sector seen from inside. Pitch tips the face up: +90 is a floor, -90 a ceiling, and on a wall +15 leans the top 15 degrees AWAY from the side it faces (a battered wall seen from inside; the face looks a little up), -15 leans it toward that side (an overhang). Yaw turns it about the vertical axis: 90 faces east (+X), 180 north (-Z), -90 west. Roll spins it about its own normal. A wall facing east is `[90, 0, 0]`, leaning back 15 degrees `[90, 15, 0]`. The MCP's `facing` + `lean_deg` and `normal` parameters compute these.
* **Floor height**: a plane's y is relative to its room, and a plane within half a fine step of a floor or ceiling draws at the same depth and flickers; lift it by a fine step or more (the MCP warns when it sees this).
* **Inspector**: position (grid units), size, yaw/pitch/roll, Wall/Floor/Ceiling orientation presets, the Tiling section (below; Tile repeats every sector from the top-left corner, Stretch puts one whole texture across), both sides, fullbright, enabled, the collision class and the camera setting.
* **Camera**: the third-person camera passes through a plane that is translucent or alpha-cut (a banner, a grate, foliage) and stops at an opaque one. The Camera row of the Inspector overrides it per plane (passes through / blocks). The character itself still collides with the plane per its collision class either way.

Collision class decides what the cook writes, from the plane's normal: None (decor) is drawn only. Walkable and Solid both collide, and the shape follows the lean: at least 0.7 up or down (flatter than 45 degrees) is a platform the character stands on, at most 0.35 is a vertical wall segment that blocks from both sides, anything between is a box around the plane (it over-blocks and the cook warns). A Walkable plane too steep to stand on reports a warning and blocks instead. A plane has to lie inside its room's sector rectangle; the editor grows the room to hold it, and the cook refuses a plane outside it.

The 3D preview and Play both draw planes with the light baked per corner like any face (a both-sided plane is lit from either side, fullbright skips the bake). Tiled planes are cut at every sector so each piece stays inside one texture repeat.

## Play

Press Play (or Build to export a disc). The editor cooks the grid document, builds the guest and starts it in the Play viewport. Nothing else is needed: there is no environment variable and no feature flag. What the cook does:

1. Validates the world against the shared caps (room size, wall stack, face budget, coordinate range). A problem stops the cook with a message such as `grid world: room 0 sector 3,4: ...` in the status line and the build log.
2. Derives thin collision slabs from the document (solid walls and walkable surfaces) plus a sky lid, and cooks them through the existing PXBSP path for collision, activation and the camera. Turn `solid` off on a wall or `walkable` off on a surface (Inspector) to walk through it.
3. Writes the render pack from the same faces the editor draws, with the light baked per corner from the Point Light nodes, the room ambient and the slabs as shadow casters.
4. Marks the manifest as a grid world; the guest build picks the grid renderer from that.

The cook warns when a texture is not 64 by 64, when faces have no material the cook can bind and when collision slabs were refused.

## Known gaps

* Camera and character: the starter and imported levels use the Graybox Reach character, which costs most of the frame.
* Free planes: translucent planes follow the engine's ordering of blended packets.
* An agent can build and play a grid level end to end through the psxed-mcp server (`docs/grid/mcp-guide.md`): the geometry tools wrap the same edit functions as the tools above.
* Brush and BSP authoring still exist for brush projects and are hidden for grid ones; the PXBSP cook is only a transitional bridge for collision.
